**Algorithm:** `QueryOptimizer.Optimize` uses an exact bitmask DP (Held-Karp/DPsub style) over table subsets. For each subset it computes the cheapest leaf plan (tableScan vs. each valid indexSeek) and the cheapest way to split it into two join-edge-connected halves across `nestedLoop`/`hashJoin`/`mergeJoin`, replicating `CostModel`'s private cost formulas exactly. Row estimates depend only on the subset (not tree shape), so they're precomputed once and reused. Canonical child ordering (by min table ID) and the crossing-join requirement are enforced via precomputed adjacency bitmasks. Exact DP handles ≤14 tables (O(3ⁿ) split enumeration); a greedy O(n³) fallback merges cheapest crossing-connected components beyond that. Determinism comes from fixed enumeration order with strict tie-breaking.
